# Gitignore Requirements

## Scope

Requirements-only mode: true.
Applies to repository ignore policy and generated local artifacts configured in `.gitignore` for this project.

R001  Statement: Exclude local build output from version control.
Design: Ignore repository-local build and binary output paths, including `bin/*`.
Rationale: Build artifacts are machine-generated and should not be committed.
Tests:
- Run a local build and verify generated files under ignored build paths do not appear in `git status`.

R005  Statement: Exclude macOS local metadata from version control.
Design: Ignore `.DS_Store`.
Rationale: Finder metadata is local machine noise.
Tests:
- Create `.DS_Store` and verify it does not appear in `git status`.

R010  Statement: Exclude repository-local Cursor rules symlink trees from version control.
Design: Ignore `.cursor/rules/*` to avoid accidental commits of local rule symlink trees.
Rationale: Local IDE rule links are environment-specific and not source of truth.
Tests:
- Add a file under `.cursor/rules/` and verify it is ignored.

R015  Statement: Keep project source and shared project configuration tracked.
Constraints:
- Do not ignore `requirements/` documents.
- Do not ignore `tests/` test files.
- Do not ignore repository scripts such as `00_*.sh` and `01_*.sh`.
Tests:
- Verify requirements, scripts, and tests remain tracked after ignore updates.

R020  Statement: Remove accidentally tracked generated artifacts from Git index without deleting local files.
Design: Use cached removals (`git rm -r --cached`) for ignored artifact paths.
Rationale: Keeps local developer caches intact while cleaning repository history moving forward.
Tests:
- Run cached removal for ignored artifact paths and verify files are staged as deletions but remain on disk.

R025  Statement: Enforce that ignored artifact paths are not tracked after cleanup.
Design: Verify `git ls-files` contains no entries under ignored build/cache paths.
Tests:
- Run `git ls-files | rg '^bin/'` and confirm no output.

R030  Statement: Exclude generated security reports from version control.
Design: Ignore `.security-reports/` and keep report artifacts local-only even when security scripts generate fresh output.
Rationale: Security scan output is machine-generated, run-specific, and should not create Git churn.
Tests:
- Run security/dependency checks and verify `.security-reports/*` artifacts do not appear in `git status`.
- Run `git ls-files | rg '^\.security-reports/'` and confirm no output.
